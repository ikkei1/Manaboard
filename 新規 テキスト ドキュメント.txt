# StudyPilot Ver1.1〜Ver1.4 要件定義書

## 0. 前提

本要件定義は、StudyPilot Phase 1 MVPの完成後に追加する機能を対象とする。

Phase 1で実装済みの機能は以下とする。

* ユーザー登録・ログイン
* 学習記録のCRUD
* ダッシュボード
* 目標設定

使用技術は以下を前提とする。

* Frontend: Next.js / TypeScript / Tailwind CSS
* Backend: FastAPI / Python
* Database: PostgreSQL
* Auth: JWT
* AI: OpenAI API または同等のLLM API
* OCR: Tesseract OCR または Google Vision API など

---

# Ver1.1 AI問題作成機能

## 1. 目的

ユーザーが指定した教科・単元・難易度に応じて、AIが学習問題を自動生成する機能を追加する。

この機能により、ユーザーは自分の学習状況に合わせた問題をすぐに作成し、練習できるようにする。

---

## 2. 機能概要

ユーザーは以下の条件を入力し、AIに問題を生成させる。

* 教科
* 単元
* 難易度
* 問題数
* 問題形式

AIは条件に応じて、問題・解答・解説を生成する。

---

## 3. 入力項目

| 項目   | 必須 | 内容                    |
| ---- | -- | --------------------- |
| 教科   | 必須 | 数学、英語、国語、理科、社会、情報、その他 |
| 単元   | 必須 | 例：二次関数、英単語、世界史など      |
| 難易度  | 必須 | easy / normal / hard  |
| 問題数  | 必須 | 1〜10問                 |
| 問題形式 | 必須 | 選択式 / 記述式 / 穴埋め式      |

---

## 4. 出力内容

AIは以下の形式で問題を返す。

* 問題文
* 選択肢
* 正解
* 解説
* 難易度
* 教科
* 単元

---

## 5. 画面要件

### `/ai/problems`

AI問題作成画面を追加する。

表示内容：

* 条件入力フォーム
* 問題生成ボタン
* 生成結果表示エリア
* 「保存する」ボタン
* 「もう一度生成する」ボタン

---

## 6. API要件

### `POST /api/ai/problems/generate`

AIで問題を生成する。

リクエスト例：

```json
{
  "subject": "数学",
  "unit": "二次関数",
  "difficulty": "normal",
  "question_count": 5,
  "format": "multiple_choice"
}
```

レスポンス例：

```json
{
  "problems": [
    {
      "question": "二次関数 y = x^2 - 4x + 3 の頂点を求めなさい。",
      "choices": ["(2, -1)", "(1, 0)", "(4, 3)", "(0, 3)"],
      "answer": "(2, -1)",
      "explanation": "平方完成すると y = (x - 2)^2 - 1 となるため、頂点は (2, -1) です。"
    }
  ]
}
```

---

### `POST /api/ai/problems/save`

生成した問題を保存する。

---

## 7. DB追加

### `ai_problems`

| カラム         | 型         | 内容     |
| ----------- | --------- | ------ |
| id          | UUID      | 問題ID   |
| user_id     | UUID      | ユーザーID |
| subject     | varchar   | 教科     |
| unit        | varchar   | 単元     |
| difficulty  | varchar   | 難易度    |
| format      | varchar   | 問題形式   |
| question    | text      | 問題文    |
| choices     | jsonb     | 選択肢    |
| answer      | text      | 正解     |
| explanation | text      | 解説     |
| created_at  | timestamp | 作成日時   |

---

## 8. 受け入れ条件

* ユーザーが条件を入力するとAIが問題を生成できる
* 生成された問題に正解と解説が含まれている
* 生成された問題をDBに保存できる
* ログイン中のユーザーの問題のみ保存・表示できる
* AI生成に失敗した場合、エラーメッセージを表示する

# Ver1.2 苦手分析機能

## 1. 目的

ユーザーの問題回答履歴をもとに、苦手な教科・単元を可視化する。

単なる学習時間の記録ではなく、正答率やミスの傾向から「次に何を勉強すべきか」を提示する。

---

## 2. 機能概要

ユーザーがAI問題に回答すると、正誤情報を保存する。

保存された回答履歴から、以下を分析する。

* 教科別正答率
* 単元別正答率
* 苦手ランキング
* 最近ミスが多い単元
* AIによる学習アドバイス

---

## 3. 回答記録

ユーザーは生成された問題に回答する。

保存する内容：

* 問題ID
* ユーザーの回答
* 正解・不正解
* 回答日時
* ミスの種類

ミスの種類は以下から選択できる。

* 計算ミス
* 暗記不足
* 理解不足
* ケアレスミス
* 時間不足
* その他

---

## 4. 画面要件

### `/analysis`

苦手分析画面を追加する。

表示内容：

* 教科別正答率
* 単元別正答率
* 苦手単元ランキング
* 最近のミス傾向
* AIからの学習アドバイス

例：

```text
あなたは「数学：確率」の正答率が40%で、他の単元より低いです。
特に理解不足によるミスが多いため、基本問題から復習することをおすすめします。
```

---

## 5. API要件

### `POST /api/problems/{problem_id}/answer`

問題への回答を保存する。

リクエスト例：

```json
{
  "user_answer": "(2, -1)",
  "is_correct": true,
  "mistake_type": null
}
```

---

### `GET /api/analysis`

苦手分析データを取得する。

レスポンス例：

```json
{
  "subject_accuracy": [
    {
      "subject": "数学",
      "accuracy": 72
    }
  ],
  "unit_accuracy": [
    {
      "subject": "数学",
      "unit": "確率",
      "accuracy": 40
    }
  ],
  "weak_units": [
    {
      "subject": "数学",
      "unit": "確率",
      "accuracy": 40,
      "mistake_count": 8
    }
  ],
  "ai_advice": "確率の基本問題を優先的に復習しましょう。"
}
```

---

## 6. DB追加

### `problem_attempts`

| カラム          | 型         | 内容      |
| ------------ | --------- | ------- |
| id           | UUID      | 回答ID    |
| user_id      | UUID      | ユーザーID  |
| problem_id   | UUID      | 問題ID    |
| user_answer  | text      | ユーザーの回答 |
| is_correct   | boolean   | 正解かどうか  |
| mistake_type | varchar   | ミスの種類   |
| answered_at  | timestamp | 回答日時    |

---

## 7. 受け入れ条件

* 問題に回答できる
* 回答結果がDBに保存される
* 正答率が教科別・単元別に集計される
* 正答率の低い単元がランキング表示される
* AIが苦手分野に対する学習アドバイスを生成する

---

# Ver1.3 AIスケジュール生成機能

## 1. 目的

ユーザーの目標、試験日、学習可能時間、苦手分野をもとに、AIが学習スケジュールを自動生成する。

ユーザーが「何を、いつ、どれくらいやればいいか」を迷わず決められるようにする。

---

## 2. 機能概要

ユーザーは以下の情報を入力する。

* 目標
* 試験日
* 平日の学習可能時間
* 休日の学習可能時間
* 優先したい教科
* 苦手分野を考慮するかどうか

AIは入力情報と苦手分析データをもとに、日別の学習計画を作成する。

---

## 3. 入力項目

| 項目        | 必須 | 内容            |
| --------- | -- | ------------- |
| 目標名       | 必須 | 例：期末テストで80点以上 |
| 試験日       | 必須 | 未来の日付         |
| 平日の学習可能時間 | 必須 | 分単位           |
| 休日の学習可能時間 | 必須 | 分単位           |
| 対象教科      | 必須 | 複数選択可         |
| 苦手分野を考慮   | 任意 | true / false  |

---

## 4. 出力内容

AIは以下の形式でスケジュールを作成する。

* 日付
* 教科
* 単元
* 学習時間
* 学習内容
* 優先度
* 完了状態

例：

```text
7月9日
数学：確率 40分
英語：長文読解 30分
復習：前回間違えた問題 20分
```

---

## 5. 画面要件

### `/schedule`

スケジュール画面を追加する。

表示内容：

* スケジュール生成フォーム
* 生成された学習計画
* 日別スケジュール一覧
* 完了チェック
* 再生成ボタン
* 手動編集ボタン

---

## 6. API要件

### `POST /api/schedules/generate`

AIでスケジュールを生成する。

リクエスト例：

```json
{
  "goal_name": "期末テストで80点以上",
  "exam_date": "2026-09-15",
  "weekday_minutes": 120,
  "weekend_minutes": 300,
  "subjects": ["数学", "英語"],
  "use_weak_analysis": true
}
```

---

### `GET /api/schedules`

スケジュール一覧を取得する。

---

### `PUT /api/schedules/{id}`

スケジュールを編集する。

---

### `PATCH /api/schedules/{id}/complete`

スケジュールを完了状態にする。

---

### `DELETE /api/schedules/{id}`

スケジュールを削除する。

---

## 7. DB追加

### `study_schedules`

| カラム            | 型         | 内容                  |
| -------------- | --------- | ------------------- |
| id             | UUID      | スケジュールID            |
| user_id        | UUID      | ユーザーID              |
| goal_name      | varchar   | 目標名                 |
| scheduled_date | date      | 学習予定日               |
| subject        | varchar   | 教科                  |
| unit           | varchar   | 単元                  |
| study_minutes  | integer   | 学習時間                |
| task_detail    | text      | 学習内容                |
| priority       | varchar   | high / medium / low |
| is_completed   | boolean   | 完了状態                |
| created_at     | timestamp | 作成日時                |
| updated_at     | timestamp | 更新日時                |

---

## 8. 受け入れ条件

* 目標・試験日・学習可能時間を入力できる
* AIが日別スケジュールを生成できる
* 苦手分析データを考慮した計画を作成できる
* スケジュールを一覧表示できる
* スケジュールを完了済みに変更できる
* スケジュールを編集・削除できる

# Ver1.4 OCR問題読み取り・AI解説機能

## 1. 目的

ユーザーが問題画像をアップロードすると、OCRで文字を読み取り、AIが問題の解説を生成する機能を追加する。

紙の教材やプリントを使っている学生でも、アプリ上で問題を理解・復習できるようにする。

---

## 2. 機能概要

ユーザーは問題画像をアップロードする。

システムは以下の処理を行う。

1. 画像をアップロード
2. OCRで文字を抽出
3. 抽出された文字を表示
4. ユーザーが必要に応じて文字を修正
5. AIが解説を生成
6. 解説結果を保存

---

## 3. 入力項目

| 項目     | 必須 | 内容                    |
| ------ | -- | --------------------- |
| 画像ファイル | 必須 | jpg / png / webp      |
| 教科     | 必須 | 数学、英語、国語、理科、社会、情報、その他 |
| 補足メモ   | 任意 | 最大500文字               |

---

## 4. ファイル制限

* 対応形式：jpg / png / webp
* 最大サイズ：5MB
* 1回につき1枚
* 不鮮明な画像の場合はエラーまたは再アップロード案内を表示する

---

## 5. 出力内容

OCR結果：

* 抽出テキスト
* 信頼度
* 修正可能なテキスト欄

AI解説：

* 問題の要点
* 解き方
* 答え
* 解説
* 類題

---

## 6. 画面要件

### `/ocr`

OCR問題読み取り画面を追加する。

表示内容：

* 画像アップロードフォーム
* プレビュー画像
* OCR結果表示
* OCRテキスト修正欄
* AI解説生成ボタン
* 解説表示エリア
* 保存ボタン

---

## 7. API要件

### `POST /api/ocr/extract`

画像から文字を抽出する。

レスポンス例：

```json
{
  "ocr_text": "二次関数 y = x^2 - 4x + 3 の頂点を求めなさい。",
  "confidence": 0.91
}
```

---

### `POST /api/ocr/explain`

OCRテキストからAI解説を生成する。

リクエスト例：

```json
{
  "subject": "数学",
  "ocr_text": "二次関数 y = x^2 - 4x + 3 の頂点を求めなさい。",
  "memo": "平方完成が苦手"
}
```

レスポンス例：

```json
{
  "summary": "二次関数の頂点を求める問題です。",
  "answer": "(2, -1)",
  "explanation": "y = x^2 - 4x + 3 を平方完成すると y = (x - 2)^2 - 1 となるため、頂点は (2, -1) です。",
  "similar_problem": "二次関数 y = x^2 - 6x + 5 の頂点を求めなさい。"
}
```

---

### `POST /api/ocr/save`

OCR結果とAI解説を保存する。

---

## 8. DB追加

### `ocr_questions`

| カラム             | 型         | 内容          |
| --------------- | --------- | ----------- |
| id              | UUID      | OCR問題ID     |
| user_id         | UUID      | ユーザーID      |
| subject         | varchar   | 教科          |
| image_url       | text      | 画像保存先       |
| ocr_text        | text      | OCR抽出テキスト   |
| corrected_text  | text      | ユーザー修正後テキスト |
| confidence      | numeric   | OCR信頼度      |
| ai_answer       | text      | AIの答え       |
| ai_explanation  | text      | AI解説        |
| similar_problem | text      | 類題          |
| created_at      | timestamp | 作成日時        |

---

## 9. 受け入れ条件

* 画像をアップロードできる
* OCRで問題文を抽出できる
* 抽出テキストをユーザーが修正できる
* 修正後のテキストをもとにAI解説を生成できる
* OCR結果とAI解説を保存できる
* 画像サイズや形式が不正な場合、適切なエラーを表示する

# 共通要件

## 1. AI利用時の共通ルール

AIに送信する情報は、必要最小限にする。

送信してよい情報：

* 教科
* 単元
* 難易度
* 問題文
* 学習履歴の集計結果
* 苦手分野の集計結果

送信しない情報：

* パスワード
* メールアドレス
* 個人を特定できる情報

---

## 2. エラーハンドリング

以下の場合は、ユーザーに分かりやすいエラーを表示する。

* AI APIの失敗
* OCRの失敗
* 画像形式エラー
* 通信エラー
* ログイン期限切れ
* 入力値エラー

---

## 3. セキュリティ要件

* JWTで認証されたユーザーのみAPIを利用できる
* 他ユーザーの問題・回答・スケジュール・OCR結果は取得できない
* ファイルアップロード時に拡張子とMIMEタイプを確認する
* 画像ファイルは最大サイズを制限する
* AIへのプロンプトインジェクション対策を行う
* APIキーは環境変数で管理し、フロントエンドに露出しない

---

## 4. パフォーマンス要件

* 通常APIは3秒以内の応答を目標とする
* AI生成やOCR処理は10〜30秒程度まで許容する
* AI処理中はローディング表示を行う
* 同一ユーザーが短時間に大量リクエストできないように制限する

---

## 5. UI/UX要件

* スマートフォンでも使いやすいレスポンシブデザインにする
* AI生成中は「生成中」と表示する
* 成功・失敗はトースト通知で表示する
* 難しい専門用語を避け、学生が直感的に使えるUIにする
* ダッシュボードから各AI機能へ移動できる導線を用意する

---

# 開発順序

## Step 1: Ver1.1 AI問題作成

最初にAI問題生成を実装する。

理由：

* AI機能として分かりやすい
* ポートフォリオで見栄えが良い
* 後続の苦手分析に必要な回答データを作れる

---

## Step 2: Ver1.2 苦手分析

AI問題への回答履歴を使って、苦手分野を可視化する。

理由：

* データ分析要素をアピールできる
* 「AIを使うだけ」ではなく「学習改善」まで示せる

---

## Step 3: Ver1.3 AIスケジュール生成

苦手分析結果を使って、学習計画を作成する。

理由：

* ユーザーごとの個別最適化を表現できる
* 実用的なサービスに近づく

---

## Step 4: Ver1.4 OCR問題読み取り

最後にOCRを追加する。

理由：

* 実装難易度が高い
* 画像アップロード・OCR・AI解説が必要
* 完成すると技術的なアピール力が高い

# 最終的な完成イメージ

StudyPilotは、以下の流れで学習を支援する。

```text
学習記録をつける
↓
AIが問題を作る
↓
ユーザーが解く
↓
正答率・ミス傾向を分析する
↓
苦手分野を見つける
↓
AIが学習スケジュールを作る
↓
紙の問題もOCRで読み取り、AIが解説する
```

この構成にすることで、単なる学習記録アプリではなく、AI・データ分析・OCRを組み合わせた実用的な学習支援サービスとしてアピールできる。
